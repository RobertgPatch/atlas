# EX-030-001: Feature 030 C1/C2 implementation exception

**Status**: Approved and active  
**Approver and owner**: Robert Patch  
**Approval/effective date**: 2026-08-29  
**Expiration**: 2026-09-28 (no automatic renewal)  
**Related remediation**: [c1-c2-remediation.md](./c1-c2-remediation.md)

## Requirements excepted

1. **C1 - failed-gate stop rule**: Feature 030's plan records unresolved feature 029 identity, MFA, Restricted-data inventory, legal/incident-readiness, and recovery evidence as `FAIL FOR REAL APPLY`. Under constitution 1.0.0, the sentence allowing implementation to continue conflicted with the categorical stop rule.
2. **C2 - authorization matrix**: Feature 030 documents actors, trusted identity sources, route classes, subject scopes, and deny behavior, but does not yet contain the explicit actor/action/resource/allow/deny/test matrix required by the constitution.

## Allowed scope

- Edit feature 030 source, tests, Terraform, scripts, specifications, and evidence.
- Run bounded synthetic tests locally and in CI.
- Commit, push, open or update a review, and merge feature 030 repository changes.
- Prepare read-only or fixture-based production validation that cannot mutate AWS or use real abuse traffic.

## Prohibited scope

- Run a real AWS production plan/apply or mutate production infrastructure.
- Route production traffic to feature 030 or claim production readiness.
- Resume or approve continued production handling of Restricted data under this exception.
- Skip, weaken, or falsify feature 030 security tests, privacy controls, topology checks, cost ceilings, or release evidence.
- Treat this exception as resolving the feature 029 identity, MFA, inventory, incident, legal, or recovery blockers.

## Risk and justification

The governance gap is documentation and activation-boundary clarity, not permission to bypass feature 030's runtime safeguards. Deferring C1/C2 avoids blocking local implementation of protections that reduce authentication and cost-exhaustion risk. The residual risk is that code could be mistaken for production-ready or access behavior could be under-specified before deployment.

## Compensating safeguards

- The plan, spec, tasks, and implementation evidence continue to state that real AWS Apply and production load testing are prohibited.
- Existing authentication and authorization remain authoritative; rate limiting may deny work but never grants access.
- All external routes remain subject to route-policy inventory and negative tests before feature completion.
- Production topology, MFA, unique identity, Restricted-data inventory, incident readiness, and recovery gates remain fail-closed.
- The follow-up document defines objective C1/C2 acceptance evidence and must be visible in review.

## Revocation and verification

This exception is revoked immediately if work crosses a prohibited scope, a new public backend path appears, an authorization control is weakened, real Restricted data enters local/CI tests, or a reachable Critical/High vulnerability is introduced. At every review and release gate, verify the current date, this status, the requested action, and the prohibited-scope list. Expiry blocks any further excepted action unless Robert Patch records a new versioned decision.
