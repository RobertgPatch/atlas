# EX-030-003: AWS production release eligibility

- **Decision owner**: Robert Patch.
- **Decision date**: 2026-09-16.
- **Scope**: AWS production releases for projectjackson.family.
- **Supersedes**: EX-030-002's expiration and its extra manual release-approval steps. EX-030-002 remains a historical record of unresolved risks.

## Sole release-eligibility rule

An AWS production release is eligible when the source is the current commit of the canonical `RobertgPatch/atlas` `main` branch and the `push` run of `.github/workflows/security-ci.yml` for that exact commit completed successfully with both **Application security gates** and **Terraform security gates** successful. A PR run, stale SHA, missing job, or skipped job does not qualify. There is no separate identity, MFA, incident-readiness, inventory, legal, cost-acknowledgement, recovery-evidence, expiration, or typed-confirmation approval gate.

This is a release-policy decision, not a claim that those operational risks have been remediated. They remain tracked in [production-activation-gates.md](./production-activation-gates.md).

## Execution correctness

AWS credentials, the exact live account and site, valid artifacts, compatible runtime configuration, successful deployment, and post-deployment health are operational necessities, not additional release approvals. A failed or mismatched execution must stop rather than deploy to another account, region, or stack. The existing Terraform workflow currently targets `us-west-2` while projectjackson.family is served from `us-west-1`; green CI alone does not make those targets interchangeable.

The operator may deploy eligible `main` without waiting for further manual sign-off. Rollback remains a separate, explicitly chosen operation. This decision does not authorize weakening the two named CI jobs or application security controls.
